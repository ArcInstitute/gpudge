# gpudge v0.3.0 — 2026-06-24

Native shard-streaming, scanpy-compatible library-size normalization, a
multi-agent hardening pass, and a published benchmark campaign. **No breaking
changes since v0.2.0** — the Mann–Whitney DE core is unchanged, so existing
`de()` calls are bit-for-bit unaffected.

Distribution stays **Arc-internal**: install from the `v0.3.0` git tag (requires
ArcInstitute SSH access); gpudge is not on PyPI.

## 🌊 Shard-streaming `de(shard_archive=…)`

Stream a [shardad](https://github.com/ArcInstitute/shardad) target-aware v2
archive directly, keeping the reference pool resident-sorted on the GPU and
streaming guide-shards past it. Host RAM is bounded to ~reference + one shard —
the full **5.54 M-cell CCL_2** screen runs in **~31 GB host RAM** on a single
H100, a dataset that needs hundreds of GB to materialize in memory.

This is a **memory/feasibility** path, **not a speedup**: streaming is ~7×
slower wall-clock than the narrowed in-memory path (serial shard decode with the
GPU idle between shards). Use it when the matrix is too large to load at all.

- **Mode 1** — the archive's own reference shard is the pooled control.
- **Mode 2** — an external `reference=<AnnData>` pool; all archive shards become
  targets. If the archive *also* carries a reference shard, gpudge now **warns
  and uses the external pool** (the archive reference is ignored) rather than
  raising — relaxed from the earlier no-reference-archive requirement. (#56)

`ALL_OTHERS` and oversized references are unsupported in this first version.
Requires the optional `[streaming]` extra. (#36)

## 📐 `de(normalize_target_sum=…)`

scanpy-compatible on-the-fly library-size normalization. Pass a positive number
(equivalent to `sc.pp.normalize_total(target_sum=N)`) or `"median"` (scanpy's
default `target_sum=None`). `cpm_normalize=True` is now exactly
`normalize_target_sum=1e6`; set at most one of the two. Works in both the
in-memory and shard-streaming paths (streaming `"median"` adds an up-front
row-sum pass over the archive). (#52)

## 🏎️ Benchmarks (vs scanpy / CPU pdex / rapids-singlecell)

Because gpudge runs the
whole screen as one GPU pass, its **DE-stage time is near-constant in the
perturbation count**, where per-group tools scale roughly linearly. Headline
DE-stage numbers on an H100 80 GB:

| Dataset | Perturbations | scanpy (CPU) | pdex (CPU) | rapids-singlecell (GPU) | gpudge (GPU) |
| --- | --: | --: | --: | --: | --: |
| CCL_1 | 500 | ~9 h | 4,285 s (71 min, 32 cores) | ~1.0e3 s | **7.2 s** |

gpudge's CCL_1/500 result is **bit-identical** to CPU pdex (log2FC & p-value
Pearson > 0.999999999 over 5.5 M gene–perturbation pairs). Above these rungs the
other engines drop out — rapids-singlecell's VRAM grows with the perturbation
count and **OOMs** (CCL_1 full, CCL_2 ≥ 200); gpudge VRAM stays flat (~15 GB CCL_1 /
~29 GB CCL_2) and keeps going at near-constant DE cost. (#50, #51)

See the README **Performance** section for the full picture, including the
full-5.54 M-cell CCL_2 "RAM by data layout" comparison (full-matrix 448 GB /
narrowed in-memory 236 GB / streaming 31 GB), all bit-identical.

## Fixed (multi-agent "ultrareview" pass)

- **Shared-validation parity** between the in-memory and shard-streaming paths:
  the legacy `reference="all_others"` remap and the `mean_calc` / `epsilon` /
  `output_columns` validation are hoisted above the streaming dispatch, so both
  paths reject identical inputs before any GPU work; the empty-archive early
  return now emits the typed canonical output schema (honouring
  `output_columns`) rather than all-`Null` columns. (#48)
- `_csr_dense` numba kernels **sum duplicate column indices within a row**
  (matching scipy `.toarray()`; previously last-write-wins, so the `[fast]` path
  could silently disagree with the scipy fallback on non-canonical CSR) and
  validate row indices are in `[0, n_rows)`. Canonical CSR is unaffected. (#48)
- OOM-recovery returns its final (possibly downshifted) gene-chunk width so the
  streaming driver carries it across target groups instead of re-OOMing per
  group; trailing-chunk H2D in the ref-mode loop is repacked contiguous to
  preserve the async pinned copy; the geometric-mean out-of-domain contract is
  pinned and documented (`X < -1` → NaN, `X == -1` → -1.0).
  (#42, #43, #46, #47, #49)

## Packaging / CI

- First CI workflow (`.github/workflows/ci.yml`): `ruff` + CPU `pytest` on every
  push / PR. Installs via `uv pip install -e ".[dev,fast]"` so the private
  shardad git-SSH source is never resolved on the runner; GPU, streaming, and
  real-data tests auto-skip. The `ruff` gate is blocking and the repo is at zero
  lint errors. (#53)
- The `[streaming]` extra's shardad pin tracks the commit carrying the
  target-aware reader API (`write_sharded(group_by=, reference=)`,
  `ShardedArchive.read_reference` / `iter_group_shards` / `read_group`), which
  postdates the shardad **v0.2.0** tag. `uv sync --extra streaming` resolves it
  from `[tool.uv.sources]`; pip users install shardad from that commit first.

## Known issues (carried from v0.1.0 / v0.2.0)

- `reference="all_others"` (lowercase string) still works with a
  `DeprecationWarning`; the removal version is deferred. Prefer the `ALL_OTHERS`
  constant.
- shardad **v2** archive loading is ~16× slower than v1 at CCL_2 scale; stay on v1
  archives for CCL_2-scale in-memory loads until shardad's on-GPU read path lands.
